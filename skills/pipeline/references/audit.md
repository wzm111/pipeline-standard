# 项目内运行记录

在未来扫描项目文件夹、比较流程开销或排查效率问题时读取。本地状态接口在运行启动、恢复和合法结束（包括paused/aborted）时，自动生成 `tmp/pipeline/runs/<run_id>/audit.json`；执行中仍由原run状态/history、检查JSON和原日志记录事实，不额外逐条记录消息或读取操作。没有接入本地接口的旧上下文不能假定已采集。

安全摘要只保留允许的技术指标：运行身份及可验证的采集实现身份、时间/状态、非重叠活动时间、任务/角色统计、检查执行/复用/继承与失败分类、完整度/缺项。不能把角色并行时间相加为总耗时，也不把测试数量当耗时。未提供的实际模型、token、纯排队和旧阶段信息保持unknown/null；没有可比样本时不计算节省百分比。

检查统计中的`check_records`是可读的check登记条数（含继承），`host_observation_records`是使用宿主观察标记的记录数。`shared_log_source_candidates`表示命令/目录/用途、环境、scope及输入/日志指纹和日志路径相同的额外记录；它只提示同日志来源，不能证明工具重复执行，也不合并coverage、删除记录或减少executed/inherited计数。两个真实新调用即使写出相同日志仍须分别保留。元数据不足时计入`source_identity_unknown`，不猜同源；旧摘要缺新字段表示未采集，需要时用只读`audit --live`核对，不当成零。统计只读取报告元数据，不为此打开原日志或核验来源链；原验收接口仍执行严格校验。新观察入口按同一ticket幂等登记，后续交付引用该唯一check，旧重复记录保持原样。

不保存owner token、receipt、环境原文、命令参数、对话、客户数据、用户目标正文或截图。原始工具输出沿用项目既有的脱敏边界；它们可能包含业务内容，默认扫描不打开。自定义阶段/分类不应无约束传播到安全摘要。

由智能体调用，只读且不要求用户配置：

```sh
python3 <runner> scan --project <项目目录>
python3 <runner> audit --project <项目目录> --run-id <明确的run_id>
# 需要当前登记元数据时，额外使用只读 --live
python3 <runner> audit --project <项目目录> --run-id <明确的run_id> --live
```

scan最多枚举1000个目录项，按候选状态文件修改时间读取最新20份（--limit可调至100），截断会标truncated。它只读已有摘要和当前状态，保留missing/legacy/stale/partial等诊断，不自动补写旧记录。单run摘要过期或缺失时，可按该接口提供的只读当前视图核对登记报告元数据；不读取raw日志、验证lineage、重新哈希项目输入或执行检查来“补日志”。摘要与原状态不一致时按过期处理，不能把旧快照当当前结果。

采集失败只返回固定安全错误类别，不影响原本的执行/停止/QA判定，不清理未知锁；开始快照和原状态仍可说明中断痕迹。摘要不是QA PASS、缓存有效性证明或重试/发布授权；复用和收口继续使用原检查/验收接口。Claude/Codex均需在实际调用点接入，不能宣称拦截了所有宿主操作。

默认不上传、不进Git，不保存另一份长报告。清理tmp会删除本地记录；长期归档只复制已确认脱敏的audit摘要，不打包私有receipt或整个运行目录。
