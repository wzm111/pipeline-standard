# 项目内运行记录

在未来扫描项目文件夹、比较流程开销或排查效率问题时读取。本地状态接口在运行启动、恢复、task-end和合法结束（包括paused/aborted）时，自动更新 `tmp/pipeline/runs/<run_id>/audit.json`。执行中可用只读 `--live` 查看已登记的变化。原run状态/history、检查JSON和原日志继续记录执行事实。没有接入本地接口的旧上下文不能假定已采集。

安全摘要只保留允许的技术指标：运行身份及可验证的采集实现身份、时间/状态、非重叠活动时间、任务/角色统计、检查执行/复用/继承与失败分类、完整度/缺项。不能把角色并行时间相加为总耗时，也不把测试数量当耗时。未提供的实际模型、token、纯排队和旧阶段信息保持unknown/null；没有可比样本时不计算节省百分比。

新摘要的`latency.samples`按已有task边界分别汇总（最多最近20段，仅匿名index；未分task时index=0表示整个已记录run）。检查区间、已闭合operation区间及登记的人工/角色等待和交接分别取并集，再对合并区间取并集；分类时间不可相加。共享任务边界上的登记计数归后一段，区间按实际重叠裁剪。继承证据不当新执行，复用只计登记次数，缺结束时间/无效时间保持null或partial，运行中的尾部只到状态快照，不外推到扫描时间。`unattributed_seconds`是尚未归因的墙钟，不能叫浪费或排队。失败分类、已确认环境差异、等待交接只生成固定`review_candidates`供后续分析，不证明根因、重复执行或节省比例。不新增采集任务，不读取raw日志；旧摘要没有latency即未采集，使用只读`audit --live`可查看现有元数据。

检查统计中的`check_records`是可读的check登记条数（含继承），`host_observation_records`是使用宿主观察标记的记录数。`shared_log_source_candidates`表示命令/目录/用途、环境、scope及输入/日志指纹和日志路径相同的额外记录；它只提示同日志来源，不能证明工具重复执行，也不合并coverage、删除记录或减少executed/inherited计数。两个真实新调用即使写出相同日志仍须分别保留。元数据不足时计入`source_identity_unknown`，不猜同源；旧摘要缺新字段表示未采集，需要时用只读`audit --live`核对，不当成零。统计只读取报告元数据，不为此打开原日志或核验来源链；原验收接口仍执行严格校验。新观察入口按同一ticket幂等登记，后续交付引用该唯一check，旧重复记录保持原样。

`task_details`给出同一批次内的实跑、复用、继承、结果分类和复用判定原因。实跑优先归到开始时所在任务，复用和继承按登记时归属。角色显示派发状态、已闭合角色区间并集、专家准备与尝试次数、宿主模型和强度反馈条数。未反馈时仍不能推断具体型号或排队时间。QA显示登记结果、机器校验记录、任务边界不符与早于tester返回的PASS。时间先后提示核对来源，不证明绕过闸口。发布显示计划是否早于首个已记录步骤、各阶段尝试和收口引用。缺少时间戳保留unknown，收口引用只说明已登记，不证明当前线上状态或证据仍有效。

只在已有调用点登记关键宿主观察和发布步骤。命令失败原因未确定时保留原分类，定位后沿用check-review修订分类。单体脚本未提供内部阶段时间时保持未知，已有发布适配器可用release_timing记录实际步骤。旧快照缺少任务明细时用`--live`读取现有可用元数据。

`qa_handoff` 分列最近检查通过、QA 报告、tester 完成登记和最终验收报告距任务起点的秒数。最终验收引用同任务更早的 QA 时增加关联计数，候选身份与证据有效性仍由原验收流程核对。`host_diagnostics` 汇总宿主失败的操作、已登记原因和关联恢复结果，仅输出固定类别及计数。旧记录没有类别时显示 unknown。

不保存owner token、receipt、环境原文、命令参数、对话、客户数据、用户目标正文或截图。原始工具输出沿用项目既有的脱敏边界；它们可能包含业务内容，默认扫描不打开。自定义阶段/分类不应无约束传播到安全摘要。

由智能体调用，只读且不要求用户配置：

```sh
python3 <runner> scan --project <项目目录>
python3 <runner> audit --project <项目目录> --run-id <明确的run_id>
# 需要当前登记元数据时，额外使用只读 --live
python3 <runner> audit --project <项目目录> --run-id <明确的run_id> --live
# 面向用户的本地预览，默认文本；不传run-id时优先当前run，否则最近记录
python3 <runner> preview --project <项目目录>
python3 <runner> preview --project <项目目录> --run-id <明确的run_id> --live --format json
```

预览复用已有audit读取与有界scan，默认不重算或保存摘要；`--live`仅在内存中根据已登记元数据计算，并分别显示当前视图来源与原快照状态。活动归属不明时拒绝自动选择，不退回旧成功记录。输出只投影固定枚举、数字、布尔值及合法时间，排除run ID、内部指纹、项目目标/路径、命令、日志正文和凭据。未知项保持未知，规则确认不代表所有规范已执行。预览不清锁、不新增报告文件，不启动进程、网络请求、浏览器或GitHub提交。本次只提供本地记录和预览，没有上传入口或自动上报配置；原始证据和日志仍受项目本地权限与脱敏规则约束。

可在本地终端执行预览命令查看。若由聊天智能体调用并展示输出，文本可能进入当前对话，处理方式由宿主决定；诊断模块不联网不等于整个宿主离线。不会在每次运行后自动把预览贴到聊天或外部位置。

scan最多枚举1000个目录项，按候选状态文件修改时间读取最新20份（--limit可调至100），截断会标truncated。它只读已有摘要和当前状态，保留missing/legacy/stale/partial等诊断，不自动补写旧记录。单run摘要过期或缺失时，可按该接口提供的只读当前视图核对登记报告元数据；不读取raw日志、验证lineage、重新哈希项目输入或执行检查来“补日志”。摘要与原状态不一致时按过期处理，不能把旧快照当当前结果。

采集失败只返回固定安全错误类别，不影响原本的执行/停止/QA判定，不清理未知锁；开始快照和原状态仍可说明中断痕迹。摘要不是QA PASS、缓存有效性证明或重试/发布授权；复用和收口继续使用原检查/验收接口。Claude/Codex均需在实际调用点接入，不能宣称拦截了所有宿主操作。

诊断功能仅在本地记录与预览，不上传、不进Git，不保存另一份长报告。清理tmp会删除本地记录；长期归档只复制已确认脱敏的audit摘要，不打包私有receipt或整个运行目录。

## 跨项目索引

`scan-projects` 从共享 pipeline CLI 读取各项目自己的审计记录，返回按快照时间倒序的 JSON 索引。原始日志、状态和证据仍由各项目保存，索引按查询即时生成。

```sh
python3 <runner> scan-projects --project <项目A> --project <项目B> --limit 3
python3 <runner> scan-projects --workspace <各项目的共同父目录> --since '2026-11-05T00:00:00+08:00' --live --format text
```

`--workspace` 只扫描直接子目录，每次最多检查 200 个目录项，最多汇总 20 个项目。`--limit` 先限制每个项目的最近候选，再按快照时间筛选。缺日期、缺快照、过期或截断都保留提示。默认读取已有快照，`--live` 只从现有登记元数据计算。

按最近已登记任务看检查复用原因、环境差异数、QA 与最终验收、发布计划与收口、宿主失败和恢复。发布命令耗时按已知覆盖标签计算区间并集，类别可能重叠。单体部署命令内部的构建、传输和就绪时间需由实际适配器用 `release_timing` 另行登记。环境变动须先核对身份及影响范围。历史记录中缺少失败原因或恢复关联时保留未知。用户可见进度仍按实际发送的消息核查。

## 多聊天共用项目的归属


宿主确实提供当前聊天ID时，执行者可在当前run或当前task起点调用`python3 <skill>/scripts/task_origin.py bind --project <项目> --receipt <本人receipt> --host-id <实际host> --thread-id <实际聊天UUID>`。只保存host与聊天ID的摘要和真实task边界；不保存聊天标题、对话或项目内容，不从旧delivery指针认领当前任务。调用方声明不是宿主证明；缺ID保持unknown，不为归属创建task、读取其他聊天或回填历史。

日后用同一脚本的`inspect --project <项目> --run-id <run> --host-id <host> --thread-id <UUID>`只读核对，或`scan --project <项目> --host-id <host> --thread-id <UUID> --limit 20`有界筛选。scan只返回明确匹配的任务时间边界，不附整份混合run耗时；无归属记录单列unattributed，不当作未使用pipeline。旧task不补写，同一task不允许改认另一聊天。所有记录留本地ignored目录，不上传。
