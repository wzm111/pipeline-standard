# QA 批次循环

standard/thorough 共用；单批打回最多 3 轮。

复用本 run 中已有的实际成功证据，须有命令、范围、时间、退出码与输出位置，且相关代码、配置、依赖、环境未变；缺证据或无法确认有效性才重跑，并补测未覆盖验收项。共享工作树全量测试期间暂停开发写入。单批需求可合并批次 QA 与终验为一次验证，不重复运行相同检查。

可用 scripts/workflow_metrics.py 的 fingerprint/reusable 核对显式输入目录（含新增/删除文件）与环境身份；必须包含实际依赖、配置与测试输入。证据还须记录输出日志的 output_sha256，缺失或日志已替换则不能复用。外部服务无稳定快照、日志缺失、命令或指纹变化时不复用。该工具不会证明调用者提供的范围已完整，也不自动执行测试；不确定影响面就重跑必需检查。指纹在稳定工作树采集，测试期间禁止并发修改。

报告归属、实际路径、检查复用及共享资源规则见[evidence.md](evidence.md)。以下路径为逻辑名，脚本模式传本run的实际报告路径，不重复生成旧路径正文。

多项验收交接共享[检查计划](check-plan.md)引用；不把final-round等执行名复制为required_checks。QA按[需求与实现核对](review.md#核对需求与实现)审查业务断言与覆盖是否完整，计划生成PASS不替代独立判断。

脚本模式以实际plan/qa/check引用为唯一检查清单与证据，不再把同一内容抄成下方手写索引；独立QA先核对冻结版本的覆盖、未决问题和差量，再补真正缺少的验证。一次命令非零先定位和分类，不自动等同一次完整业务QA打回；已经形成的QA FAIL/CONCERNS仍按原规则保留和处理，不重置上限或自动放行。

## Artifact

- `tmp/pipeline/qa/index.md`：每批一行 `batch | gate | round | report | final-items`。
- `tmp/pipeline/qa/<batch>.md`：只保留当前轮完整结果；末尾历史表只保留 `round | gate | 失败编号 | 处理结论`，不得保留旧轮全文。
- `tmp/pipeline/qa/final.md`：全部批次后的一次终验层结果和去重人工确认项。

## 循环

1. developer 完成一批后一次性勾选该批 checkbox，只跑 context 标注的快速/定向检查并简报。
2. 仅在交付输入冻结且生成目录/浏览器状态等资源无冲突时，让qa测本批、developer开下一批；冲突则顺序执行或显式隔离。qa期间developer不改已交付输入，收到打回后再暂停当前批修复。真实浏览器验收通过后按[browser-handoff.md](browser-handoff.md)保存recipe；复测及发布先复用有效脚本/样本并短查页面条件，缺前置条件时停止盲等，不重写整套测试。
3. qa 只核本批核心验收和快速层，先核对developer交接的高影响边界用例与证据是否覆盖真实输入，再补缺口，不把这些边界留到终验才首次发现。后续批次半成品导致的范围外报错只记录观察，不判 FAIL；跨批回归、重型命令和探索项写入 final-items。
4. `FAIL`：qa直接把失败编号、复现、实际/预期发给developer；修复后先复测失败项、影响面和受影响快速命令，未受影响的检查须核对输入/环境/日志指纹后复用。命令非零先分类，已给出的QA FAIL不因分类或改批次名重置打回上限。
   同根因经定向修复和复测仍失败，或开发与QA对根因存在具体冲突时，在仍允许继续的范围内按[专家短诊断](expert-advice.md)做一次指导；无触发条件不增加角色，建议仍交原开发执行、原QA核验。已到三轮或人工等待不借此自动续跑。
5. `CONCERNS`：暂停并读取 `operations.md` 的裁决规则；用户决定修复或豁免后再继续。
6. `PASS`：保存当前验收并封版；脚本模式沿用原QA报告，手写模式更新index。需要独立QA时，先登记主会话/开发的机器检查结果，独立QA真实返回后再写该批最终结论。交接引用同一候选和已有检查，QA只补证据缺口。每批只向用户发一行；表格快照仅用于等待、预算预警和异常。
   机器检查结果、QA 报告、tester 完成登记及最终验收分别反馈。已有 guardian 最终验收报告时，在 `acceptance` 的 `qa_ref` 填入同任务、同候选的真实 QA 报告引用，沿用已有候选和检查引用。tester 在返回前写出的 QA 报告保留原时间，最终验收仍按原闸口核对。
7. 全部批次结束后，qa只核未决项与尚未覆盖的终验。 并行成果合并后，若共享接口、默认值或配置发生变化，在当前候选上定向复测受影响的调用方，包括本轮新增入口。把缺少覆盖的路径纳入现有终验计划，仍有效的证据按原规则复用。脚本模式沿用原plan/qa引用，手写模式只读index与final-items并写final.md，不重读全部PASS正文或重跑有效检查。

重构中替换依赖内部实现的旧测试时，先在现有检查计划或 QA 记录中，将旧测试保护的行为逐项对应到实际调用入口的断言，包括适用的失败和边界行为。在当前候选上确认替代测试通过后，再移除已被覆盖的旧测试。仍有独立覆盖价值或尚未补齐的旧测试继续保留。
