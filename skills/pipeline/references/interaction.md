# 对话操作

这是用户入口规则；用户说目标，智能体维护文件。不要把内部 JSON、安装命令、占位符表格当作必填表单交给用户。

## 常用表达

| 用户表达 | 行为 |
| --- | --- |
| 帮我接入/初始化 | 检查当前项目，补全契约并简报 |
| 帮我实现…… | 未接入则先自动接入，再完成原需求 |
| 配置模型/开发用…… | 自动识别当前运行时，按 models.md 保存 |
| 查看设置/现在用什么模型 | 展示当前端的有效设置及来源，不改文件 |
| 架构改成……/测试恢复继承 | 仅修改所指角色和运行时 |
| 只这次用…… | 仅本次覆盖，不写持久配置 |
| 以后所有项目用…… | 保存个人默认，不覆盖已有项目设置，并说明优先级 |
| 快一点/仔细审查 | 在风险允许内选择执行档位，不擅自替换模型或跳过测试 |
| 继续/进度/停止/修复中断 | operations.md；不重新初始化 |
| 帮助/不知道怎么用 | 给“直接描述需求、配置模型、继续上次”三个示例即可 |

设置请求已经明确且可执行时，保存后展示一句结果，不再要求用户重复确认。真正有歧义才问，例如“架构”同时指规划和独立审查时，默认解释为 planner 并说明；用户说“架构评审”则对应 scope_guardian。不要把对话中的示例配置当成用户已选择的模型。

## 首次接入

1. 定位用户指定或当前项目根。只读扫描根规则、README、包/构建清单与测试配置，确定现有目录、技术栈和真实命令。不要读取密钥、扫描整个项目或安装工具来完成设置。
2. 使用仓库 templates/PIPELINE.md 的 ①–⑥ 结构，由智能体生成精简的 PIPELINE.md。已有契约只补缺项，不能覆盖禁区、确认策略或已配置命令。没有 PRD/设计稿写“以本次需求为准/未提供”，不要要求填写可选字段。
3. 默认 standard（低风险可自动 fast）、人工上线、不自动提交/推送/部署、低风险在既有授权内直接开发、模型继承。测试命令必须来自真实脚本/项目规则；没有测试设施则记录缺口和实际可做的验证，不能编造命令或标通过。
4. 写范围限于本次需求的源码/测试/文档目录及 tmp/pipeline/，排除密钥、生成物和无关目录。同步生成具体有效的 pipeline-guard 白名单，不能留 ❏ 或放行整个项目。关键范围无法判断时只问缺失边界。
5. 在 .active 创建前完成接入。若当前端已安装且需要 hook/gitignore 接入，可由智能体执行仓库 init-project.sh 的对应 --claude/--codex 模式（已生成的契约不会覆盖）；检查安装的 hook 实际存在与最终设置，缺 hook 则说明尚无机器拦截，不能谎称启用。不要为 Codex 创建 Claude 配置。不修改其他已有 hook。
6. 简报“已识别项目、验证方式、默认不提交”，有原需求继续执行；仅初始化则结束。不引导用户手填配置，除非用户主动要求。

## 设置的保存

模型设置遵循 models.md。预算、默认档位、人工闸口等流程偏好保存到 PIPELINE.md ⑥，上线选择到 ④；修改前读取原文，精确更新相关条目。用户未提及的项目规则和另一运行时设置保留。自然语言请求不能绕过更高优先级的权限与组织策略。

保存后回读确认；失败时说明尚未保存，不声称生效。配置文件语法损坏时先保留原文，提出最小修复，不覆盖成默认值。设置期间发现已有活跃流水线，只读查询可继续；持久修改等该 run 安全结束后应用，不删除锁绕过保护。
