# 本批真实使用观察与优化（2026-10-28）

按用户授权等待本批两处交付全部收口后实施，只修改 pipeline-standard。本批发布均已完成；后续新需求不再纳入。观察原始记录保存在忽略目录，不包含客户内容、凭据或私有运行凭证。

## 证据与判断

| 观察 | 判断 |
| --- | --- |
| 前一轮约51分钟的开发样本执行35次检查，没有同命令、输入和环境的重复成功对 | 不能把全部测试当作浪费，也不能据此删掉全量门禁 |
| 共享逻辑影响另一调用入口，完整单测发现两个失败，修复后复验通过 | 定向检查实际调用方的上下文、默认值和入参应前置，终验仍保留 |
| 首次浏览器填写不存在的目标，等待60秒才失败；修正后运行约7秒 | 短探测须进入standard和developer实际操作点，不能仅写在tester交接说明里 |
| 本批一处发布继承开发验收，定稿后构建一次，以已有skip-build入口上线 | 发布去重确有采用，不应再增加一套全量发布测试 |
| 另一处关联发布的功能、产物与线上冒烟证据齐全，交付凭证完整 | 变更发布输入后的必要复验与无效重复应分开 |
| 已通过QA的一处发布，可复用矩阵仍缺unit、lint、preflight | QA结论与缓存证据完整度是两件事；旧记录未带完整拒绝理由，不能仅据此判断漏测或断言只由版本号引起 |

当前run由实际启动结果、时间与最终状态绑定；命令里出现的历史run不作为当前样本。发布承接以用户明确续用和delivery来源关联。本批没有宿主实际token或实际模型身份数据。

## 已实施

1. **共享入口快检前置**：developer在修改共享函数、默认值和入参时先定位实际调用方，使用已有定向测试核对各入口；不新增清单文件、不提前重复全量。standard直通采用同一规则。
2. **首次浏览器短探测接到调用点**：standard和developer直接引用浏览器规则；提供Playwright可见性短查示例。页面正常加载与hydration等待保留；目标缺失时停止依赖操作，定位原因后有界复验，不能把短查当成业务通过。
3. **检查未复用原因直接返回**：统一入口及CLI返回并保存reuse_decision，区分无匹配、影响面未确认、输入/环境/日志/覆盖变化或原检查失败。最新同命令、范围和用途的失败阻止跨环境回退旧PASS；不输出环境原值。
4. **交付缺项可解释**：凭证保留被排除检查的引用、覆盖类别与失效原因，跨承接保留诊断。finish直接返回缺项及原因。被排除记录不作为可继承成功证据，文件恢复也不会自动重新纳入。

版本无关的依赖身份接口继续沿用既有显式声明机制，未自动忽略package/lock、未把源码等价检查改贴成unit/lint、未把旧现场预检当作新现场观察。

## 验证与限制

定向行为回归及一次全量终验通过：273项Python测试、Codex隔离安装冒烟、Shell语法和差异检查；skill格式校验通过。新增用例验证缓存失效原因、跨环境最新失败、交付失效诊断、文件恢复不复活旧凭证及CLI缺项输出。一次测试发现命令因文件名含连字符未收集用例，保留原非零结果并改用仓库规定的显式测试入口，未计为产品回归。

这些改动减少盲等和重复诊断，并将可预见的兼容问题提前暴露；不证明真实项目质量等价或固定提速比例。指令是否被各宿主实际采用、未来任务的关键路径与token降幅仍需真实使用验证。本次未启动模型对照实验，未修改外部项目或全局设置，未推送、发布或安装。
