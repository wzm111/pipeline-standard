# 第六期：pipeline-standard 本项目自试点

日期：2026-10-26。用户明确先在本项目开展，其他项目后续考虑。本记录不是多项目生产验收，也不是完整自然语言E2E自动测试。

## 本轮真实使用

- 用户通过对话选择五角色模型，智能体保存 pipeline.models.json，没有要求用户编辑配置。
- 自动为本仓库建立 PIPELINE.md，保留既有 README/路线图改动并随基础提交保存。
- 实际请求并完成planner（Astra中）、developer（Sol中）、guardian（Astra高）、tester（Sol中）任务；developer/guardian/tester后续复用。宿主没有返回实际服务端模型身份，仍为unknown。
- 用户要求逐期中文提交，已逐期执行；没有自动推送、打tag或发布。
- 用户缩小试点范围后，记录范围变化并继续本项目，不访问其他仓库。

## 本地集成验证

tests/test-selfhost.py以本项目契约建立隔离临时项目，执行：配置保存→启动run→状态只读→活动期间禁止配置修改→真实CLI解析→证据指纹→暂停→恢复→更新→完成。确认产物保留、锁清理，以及旧文本锁不被自动认领/删除。测试不启动真实模型，停止证据来自夹具确实没有执行者。

本轮早于新生命周期工具启动，使用已知归属的旧标记；收口保留旧state与报告，不宣称已经把本轮全程运行在新状态引擎上。新状态路径已接入skill规则，下一次run可使用脚本接口。

## 哪些流程优化值得保留

1. 文档与简单任务由主会话完成，不为每个任务编号启用五角色。
2. 同一角色跨阶段续用，交接只发新增范围；第四期初始化和生命周期按文件分工并行，避免共享文件冲突。
3. 定向测试成功证据复用，独立角色补测风险边界；只在阶段收口跑全量，脚本测试耗时远低于角色交接。
4. 独立审查确有收益：发现Codex-only被无关Claude链接阻止、deny禁区链接绕过；tester发现C组污染A/B判定。以上均修复并新增回归。
5. 不为中文提交创建发布agent；用户已有授权由主会话执行精确文件提交。
6. 恢复机制优先简单、可重试：去掉两文件token轮换，降低中途失败导致状态不一致的风险。

- Claude专用角色文件保存/加载刷新仍由调用方处理，纯参数转换不等于端到端应用。
- 真实A/B需求基线尚未执行；六任务方案已冻结，但达到第三期发布门槛需12任务、每组至少两次以及真实验收记录。

- Bash启发式不是完整安全沙箱；不得把本地hook回归当成任意命令防护证明。
- 多项目试点按用户要求延后，不声明已达到v4.0稳定发布门槛。
