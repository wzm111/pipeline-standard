# v3.14.10 高风险实施与人工等待门禁

- 高风险任务写入项目文件前，须通过方案评审并进入实施阶段。写入目标须落在已接受的原生开发派发所分配的范围内。门禁覆盖已配置的 Claude 编辑 hook、写入预检，以及受管检查声明的项目写入。
- 按任务开始时的 Git 基线检查项目变化，包括已提交的变更。发现改动时，收口须有实施记录、已完成的开发派发及模型路由证据。工程 QA 结论仍可独立记录。
- 旧人工等待未解除时，验证、角色派发和新任务均不能推进。通过 `continue` 登记实际恢复证据后再继续。

High-risk source writes require an approved solution, entry into implementation, and an accepted developer dispatch covering the target paths. Closeout checks changes against the task's Git baseline and validates dispatch and model routing evidence. An unresolved human wait blocks verification and dispatch until explicitly resumed.

本次变更通过 787 项本地 Python 测试、Codex 冒烟测试及 Shell 语法检查。
