# v3.10.0：开发到发布去重与角色模型路由

Claude Code 与 Codex 共用同一套对话入口；用户描述需求，智能体维护配置、检查和交付证据。

## 更新

- 角色支持按任务类型、风险和复杂度分流模型，仅明确低风险简单任务采用用户配置的轻量路线；复杂或不明任务保留基础模型。两端型号分别保存，保留宿主检查。
- 前台检查统一执行、计时、分类与保存报告；有效结果自动复用，资源冲突按声明隔离或顺序执行。
- 报告绑定run，记录阶段及角色准备/工作/等待和续用；并行时段按并集合并，缺数据保持未知。
- 验收完成自动封存交付凭证，提交与发布可跨run承接；原始来源、输入、环境、日志和QA变化均阻止相关复用。
- 浏览器脚本、合成样本和产物引用跨阶段沿用；版本无关源码检查可使用独立依赖身份，版本敏感构建与产物校验保留。
- 普通提交不额外创建角色，不因阶段切换重新规划、重读全部报告或重跑全量。最新阶段失败、暂停或中止时不默认回退旧PASS。

## 验证与限制

实现提交26281f7通过186项Python测试、安装冒烟、Shell语法及skill校验；独立审查发现的边界问题修复后复核通过。隔离实测三阶段同一检查只执行一次，失效证据重新验证。发布阶段仅变更版本说明与README，复用该实现的行为测试结果并核对文档差异，不重复执行全量测试。

通用安装模板继续继承运行时默认，升级保留个人选择。模型请求与宿主实际反馈分开记录；没有反馈时仍为unknown。尚无真实需求同任务A/B结论，不承诺固定提速或token降幅。

已有会话和角色不会仅因文件升级自动刷新规则；后续调用pipeline时加载新入口，续用角色由调度员传入简短差量。无需用户编辑配置。
