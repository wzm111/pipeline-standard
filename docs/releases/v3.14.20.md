# v3.14.20 发布收口与历史验收证据

- 发布状态在建议收口或结束前复核验收证据。若当前证据有缺口，`inspect_closeout` 会说明应检查首次收口条件还是已有收口记录。已激活的候选可继续完成线上回读和验收。
- 一次发布验收内复用已读取的报告和摘要，每份历史 QA 仅依据当时已登记的执行和绑定。下一次状态查询及写入前的复核会重新读取证据。
- 高风险 Codex 路由核对支持宿主附加的单个 `codex/` 模型名前缀，保留原生派发参数、实际反馈和推理强度核验。
- 本地和 CI 的回归入口逐文件检查安装脚本、初始化脚本和两个 hook 的 Shell 语法。Codex 与 fast 指引补齐启动参数，检查计划文档给出同身份重跑与祖先 QA 的签核示例。

本地回归使用隔离夹具验证门禁和命令行为。真实 Codex 与 Claude 会话的采用情况按各自宿主的实际观察记录。

Release status now validates acceptance evidence before recommending closeout or finish. It reports a reason when closeout needs attention. Each historical QA uses the evidence available at its own checkpoint. Codex routing accepts the host’s optional model prefix and preserves the recorded request, feedback and reasoning effort. The local and CI suite checks each shell script individually. The guides include startup arguments and a complete historical evidence example. Native-host adoption is assessed separately from local regression tests.
