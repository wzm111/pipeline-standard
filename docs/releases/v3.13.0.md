# v3.13.0：检查前置、复用诊断与真实进度

本版本针对实际运行中就绪检查滞后、检查计划缺项、复用原因不明和执行状态难以区分的问题，增加四项兼容更新。保留原质量门禁、失败记录、QA轮次上限及本地数据边界，不新增上报或报告上传。

## 四项更新

- 检查计划支持可选 `depends_on`。环境、认证或预览就绪短检查可以先于依赖项执行；缺引用、依赖环及失效前置在启动前拒绝。原 quick-before-final 门禁和无依赖计划继续适用。检查内容由智能体按实际项目维护，不自动猜测业务端点。
- 新增只读 `plan-preflight`，`verify` 自动采用同一整计划预检。提前核对所需覆盖、目录、运行器、调用名称及声明资源；阻塞时不启动后续检查。有效缓存无需写入时仍可按原规则复用；重名拒绝不覆盖旧报告，静态就绪不等于业务验收通过。
- 新增只读 `reuse-preflight`，与真实执行共享严格证据判断，返回可复用性、拒绝原因和下一步。影响范围未确认仍拒绝；不放宽输入、环境、日志及最新失败校验，不输出环境原值、日志或凭据。查询结果不能替代实际执行时的再次核验。
- 进度摘要分开显示执行段、交付状态和显式宿主反馈。`task-end` 不再容易混同验收完成；外部等待、过期停止反馈及登记状态冲突明确标示。查询不探活、不重启、不清锁，也不会自行向其他聊天发送进度。

详细接口见[检查计划](../../skills/pipeline/references/check-plan.md)、[证据与复用](../../skills/pipeline/references/evidence.md)和[可见进度](../../skills/pipeline/references/progress.md)。用户仍通过自然语言使用，无需额外配置。

## 验证与限制

四项实现已分别提交，并通过独立复核；本地41个Python测试文件共524项测试、Codex安装冒烟、Shell语法和差异检查通过。验证期间保留环境身份变化和生成字节码导致的证据失效记录，使用真实隔离输出环境完成同进程验证与收口，没有忽略环境键或将失效证据标为通过。

额外的skill-creator校验器因本地Python缺少`yaml`未能启动；本次未修改skill入口frontmatter，也未安装全局依赖。发布阶段另外核验目标提交的Ubuntu与macOS CI、公开标签及发布元数据，不重复无源码变化的本地全量回归。

这是本地实现与行为验证，不证明所有执行会话已刷新规则或获得固定提速、token收益。实际型号、token和纯排队时间未采集时仍为未知。已有会话按需刷新本次引用，保留当前目标及有效检查，不强制重启或重做。
