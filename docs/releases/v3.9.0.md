# v3.9.0：可靠配置、运行恢复与本项目回归

本次发布汇总六期本地实现，继续采用对话式入口与按需角色编排。无需手填配置；已安装的仓库软链接更新后，新开会话加载。

## 新增与修复

- 模型配置支持项目/个人/本次覆盖、恢复继承与删除覆盖；项目保存具备原子替换、revision检查、回读和活动run保护。
- Codex与Claude采用各自的纯参数适配；模型权限未知与不可用明确区分，仅在用户授权时回退。请求模型和宿主实际反馈分开记录。
- 增加有归属的运行状态、只读查询、暂停/恢复与完成接口，保留历史产物；未知锁不自动删除，停止执行者仍由宿主负责。
- 修复初始化遗漏已有matcher中的pipeline hook、Codex-only被无关Claude符号链接阻止的问题，保留既有配置。
- 修复直接编辑路径的遍历/符号链接边界、单文件白名单和deny链接别名检查。
- 增加输入与环境指纹、输出日志hash核验、A/B配对统计与并行区间去重；C组单独报告，不干扰A/B结论。
- 增加统一本地回归入口及macOS/Ubuntu CI配置，完成本项目隔离集成测试和分期实施记录。

## 验证与限制

61项本地行为测试、Codex安装冒烟、Shell语法、差异检查和skill校验通过。执行 `bash tests/run-all.sh` 可复查本地回归；不会调用模型或更改个人配置。

两端真实模型切换尚未完整验收：当前Codex子任务请求能够完成，但宿主未返回实际模型身份；本机Claude最小调用因缺少native binary失败，未自动重装环境。纯参数适配和配置解析不能替代真实调用验证。

真实A/B需求基线尚未采集，不发布速度或token节省百分比。CI配置已加入，远端运行结果需另行查看。用户指定本轮只在pipeline-standard试点，多项目验证延后。

hook的Bash检查为启发式，不是完整沙箱；Codex写前校验与Claude直接编辑hook的保障层级不同。本版本不代表路线图全部验收或v4.0稳定性目标已达成。

## 升级与后续

模型配置保持schema_version=1，不强制改写旧项目。运行中任务不因更新自动切换模型；旧纯文本锁需核对归属，不能直接删除来迁移。
