# 开发与发布去重

本次针对实际使用中重复准备、跨run无法自动复用及发布重新验收的问题优化pipeline本身，不修改业务项目或部署脚本。

## 调度行为变化

- 同一需求的验收、提交、发布沿用交付链，普通提交和摘要不新增角色；已有角色只接收差量。
- 正常检查调用统一入口，影响范围明确时自动查找有效结果，命中后跳过执行，不再要求智能体每次手动查日志与拼接reuse_from。
- finish在原归属锁内自动封存QA通过及可复用检查；后续阶段显式delivery_from承接。普通新需求不自动继承其他交付。
- 浏览器脚本、样本和产物的路径与原指纹跨阶段传播。失效项独立处理，不能因提交阶段再写一次就变成已验证。
- 源码检查与版本/构建身份分别声明范围。明确版本无关时，依赖身份只规范化三个根版本字段；依赖、脚本、配置变化仍失效，版本敏感检查保留原输入。

## 质量边界

来源必须是同项目已完成run，QA及可选验收通过，所有引用、契约、输入、环境和日志有效。继承记录保留来源链，统计不冒充当前run执行。最新交付失败、未验收、暂停或中止时阻塞latest，不静默回退旧成功；陌生旧报告不自动认领。

发布保留权限、备份、候选版本/提交身份、产物完整性和少量线上关键路径冒烟；不因开发测试已通过就省略目标环境验证。用户指定逐项提交的粒度不改变。旧角色续用应收到这次入口和差量验收要求，无需重读整段历史。

## 已验证

隔离项目实测三阶段的同一检查只执行一次，提交与发布复用；修改源码、依赖、环境、QA、日志、原报告或契约均使对应证据失效。版本无关源码检查沿用，版本敏感构建重新执行。不同项目、失败源run和部分导入写失败不认领。

独立审查发现并修复了两处问题：旧成功指针在新验收失败后被误用，以及第三阶段丢失浏览器资产引用。修复后定向复核通过，未发现新增P1/P2。新增14项交付链和9项依赖身份测试，全部186项Python测试、安装冒烟、Shell语法、空白检查与skill校验通过。全量经统一入口实际执行，前后输入稳定。

这是本地行为与流程验证，尚无真实项目同任务A/B数据，不承诺固定提速或token降幅。外部项目、全局配置未修改；本轮中文提交，不推送或发布。
